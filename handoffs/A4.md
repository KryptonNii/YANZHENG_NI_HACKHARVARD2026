6. `importers/protocol_extract.py`: pdfplumber text/tables -> locate Schedule of Activities -> LLM structured output -> validation. Candidates only, never auto-applied.
7. `importers/router.py`: `POST /ctgov/{nct_id}`, `POST /protocol`; audit via `compliance.audit.append`.
8. Tests: golden mapping on real fixtures, offline/network failure, synthetic reportlab PDF (LLM mocked), accuracy recorded here.

## Done
**How to run.** A5 mounts `trialpilot_api.importers.router` at `/api/import` (`api/trialpilot_api/mounts.py`), so `make dev` or
`docker compose up` serves it. Offline demo: `DEMO_OFFLINE=1` (no network call at all; everything comes from `data/fixtures/`).

| Endpoint | What it does |
|---|---|
| `POST /api/import/ctgov/{nct_id}` | registry study -> `{design, raw_cached, stale_fallback, missing_fields, notes, field_sources, enrollment_type, drug_type_basis, visit_template_id, geocoded_site_ids, unresolved_site_ids, sponsor, collaborators, dates, documents, source, attribution}`. Bad id -> 400 `invalid_registry_id`; not found -> 404 `study_not_found`; offline and not cached -> 503 `offline_cache_miss`; network down -> 503 `registry_unavailable` (or the cached copy, flagged `stale_fallback`). |
| `GET /api/import/ctgov` | studies in the local cache (the UI's offline demo chips) |
| `POST /api/import/protocol` | multipart `file` (PDF <= 20 MB, else 413) **or** form `nct_id` (uses the protocol on ClinicalTrials.gov) -> `{candidates, warnings, soa_pages, method, model, excluded_columns, notice: "DRAFT …", auto_applied: false, …}`. Each candidate has `source_page`, `quote` (<= 25 words), `confidence`, and per-procedure evidence. |
| `POST /api/import/protocol/apply` | design + the visits a human accepted -> new design with `visits` replaced and `"visits"` removed from `missing_fields`. Never called automatically. |
| `POST /api/import/protocol/review` · `GET …/review/stats` | logs accepted / edited / rejected / added counts per review (accuracy metric). |

Every successful import, extraction, apply and review writes an audit entry (A7's chain, through A5's adapter). If the audit
can't be written, the request fails with 503 `audit_unavailable` and no result is returned.

**Identity (fixed this round, URS-023).** In A5's app the role comes from A7's registry through A5's `deps.resolve_identity`.
A claimed `X-Role` that differs -> 403 `role_mismatch`; an unknown user -> 403 `unknown_user`. Apply and review are human
confirmations: anonymous -> 401 `identity_required`, viewer -> 403 `forbidden_role`, any `ai:*` actor -> 403
`ai_confirmation_forbidden`. (Inside A5's app an `ai:` name is already refused by A5's header format check -> 400
`invalid_identity`; the router's own check is defence in depth.) Import and extraction stay open to anonymous callers
(public data, audited as `anonymous`). Checked in-process through `create_app` on 2026-10-16: anonymous 401, `val.viewer` 403,
`ai:extractor` 400, `alex.author` 200. **Depends on A5's `deps.resolve_identity`.** When I committed, it was in A5's working
copy but not yet in a commit. Without it the router falls back to the headers (as before), and
`test_real_app_takes_the_role_from_the_registry` skips instead of failing.

**The demo uses NCT03930732 (BOREAS):** a Regeneron/Sanofi biologic, the largest-but-one site network (275 sites, 24 countries),
completed with actual enrolment, and its protocol is posted on ClinicalTrials.gov. The protocol's Schedule of Activities
covers 19 site visits and 293 procedure-at-visit items. So the "registry facts -> protocol schedule -> levers" story runs end to
end, offline. Drug type for both dupilumab trials is `biologic` because of the INN stem `-mab`: the registry itself types the
intervention as DRUG (the note says so).

**Measured numbers (honest scope).**
- *Geocoder* (offline GeoNames, no web geocoder): on every site that has a registry geoPoint (819 sites, 4 trials), the city/state/
  country lookup matched **816 / 819 (99.6 %)**. Of the matches, **810 (99.3 %)** fall within 25 km of the registry point and 809 within
  0.5 km; the worst is 363 km. The near-zero median means the registry's geoPoints coincide with GeoNames city coordinates, so
  this measures city-name matching (city centroids), not facility location. Sites the index can't place stay unresolved
  (lat/lon empty, listed); a country centroid is never guessed. 3 BOREAS sites are placed only to state level, and the note says so.
- *Extraction, deterministic table parser* on the synthetic text PDF (`tools/make_synthetic_protocol.py`, 5 pages, SoA on
  pages 3–4): **7 / 7 visits, 7 / 7 weeks, 1 / 1 windows, 50 / 50 procedure items (precision 50 / 50, recall 50 / 50)**. That's 100 % on
  a document we generated ourselves; it shows the parser works, not how it does on real protocols.
- *Extraction, LLM vision path*: tested **only with a mocked LLM** (the mock returns the ground truth plus planted defects). That
  tests the validator (clipped quotes, out-of-SoA pages -> confidence <= 0.3, unknown labels -> `other:<label>`, home-dosing columns
  excluded), **not the model**. **Live-model accuracy was NOT measured**: no `ANTHROPIC_API_KEY` exists in this environment.
- *BOREAS cached extraction*: the SoA in that PDF is embedded as page images. The coding agent (Claude Opus 5.5) transcribed it
  from rendered pages at build time (`data/fixtures/protocols/NCT03930732_soa_transcription.yaml`), and it passes through the same
  validator. It is **not human-verified** (`provenance.human_verified: false`), and its accuracy is not measured.
- *Review log*: `GET /api/import/protocol/review/stats` gives the real accuracy metric (share of candidates a human accepted unchanged).
  The one entry in the dev cache (19/19 accepted, 2026-10-17 01:46 UTC) came from a UI test run, not a human check, so it is
  **not** an accuracy figure.

## Not done / stubbed
- No live LLM run (no key). With a key: `EXTRACT_MODEL` defaults to `claude-opus-5-5`; the code path is in `importers/llm.py`
  (structured JSON-schema output, one retry, clear errors).
- No human verification of the BOREAS transcription yet. To get a defensible accuracy number: a person opens the BOREAS PDF (link in
  the transcription file), reviews the 19 candidates in the Import page, and the review log records accepted / edited / rejected.
- The visit template's per-patient length comes from the longest registry outcome time frame. For BOREAS that is the safety window
  ("… + 98 days, up to 491 days" -> 70.1 weeks), longer than the protocol's 52 + 12 weeks. The note states the basis. The demo
  replaces the template with the protocol schedule anyway.
- `sample_temp` stays empty on purpose (A2's note): storage temperatures must come from the protocol or lab manual, and the BOREAS SoA
  doesn't give them. The engine's "shipped as ambient" warning is the honest outcome. A default, if wanted, belongs in A10's library
  as a flagged assumption, not in the vocabulary.
- Per-site expected enrolment isn't in the registry, so it stays empty and `sites.expected_enrollment` is listed in `missing_fields`.

## Known risks
- `DEMO_OFFLINE=1` with a study that isn't cached -> 503 `offline_cache_miss`; only the 4 NCT ids above are cached.
- With a key and no cache, image-only SoAs go to the LLM (sends up to 8 page images to Anthropic, up to 180 s, one retry).
- Registry data in the fixtures is a snapshot (2026-10-16). The terms ask distributors to keep it current: `refresh=true`
  re-downloads it.
- GeoNames name matching can pick a same-named city in the right country (the 363 km worst case); state is used when the
  registry gives one.
