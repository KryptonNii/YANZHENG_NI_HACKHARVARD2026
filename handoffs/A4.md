# A4 Importers — HANDOFF

Last updated 2026-10-16 (ET), A8 interface fix. Import notes now name the field they explain and
whether they are a fact, a missing field, or an assumption. Procedure codes have a category
`group_label`. Review stats take optional `bulk_accepted` and do not turn a bulk accept, or an old
log line, into an accuracy rate. Live-model accuracy was not measured. Geocoder match counts and
the synthetic-parser counts below are the earlier measurement; the tests that guard them still pass.

## Plan (written at start, 2026-10-16 21:05 ET)
1. Verify ClinicalTrials.gov API v2 field paths against the official docs and real saved responses.
2. Pick 2–3 real Phase 3 trials (>= 50 sites with geoPoints, one biologic, ideally Regeneron/Sanofi) by fetching them; save raw JSON (`data/fixtures/ctgov/`) + mapped `TrialDesign` (`data/fixtures/trials/`).
3. `importers/ctgov.py`: `fetch_study` (disk cache, `DEMO_OFFLINE=1` = cache only, rate limit, timeout + 1 retry) and `map_study` -> `TrialDesign`.
4. Visits from `data/fixtures/visit_templates.yaml` (every template `assumption: true`); `"visits"` always in `missing_fields` unless a protocol extraction is applied.
5. `importers/geocode.py`: offline GeoNames index (CC BY 4.0) for sites without geoPoint; measure error against real CT.gov geoPoints.
6. `importers/protocol_extract.py`: pdfplumber text/tables -> locate Schedule of Activities -> LLM structured output -> validation. Candidates only, never auto-applied.
7. `importers/router.py`: `POST /ctgov/{nct_id}`, `POST /protocol`; audit via `compliance.audit.append`.
8. Tests: golden mapping on real fixtures, offline/network failure, synthetic reportlab PDF (LLM mocked), accuracy recorded here.

## Done
**How to run.** A5 mounts `trialpilot_api.importers.router` at `/api/import` (`api/trialpilot_api/mounts.py`), so `make dev` or
`docker compose up` serves it. Offline demo: `DEMO_OFFLINE=1` (no network call at all; everything comes from `data/fixtures/`).

| Endpoint | What it does |
|---|---|
| `POST /api/import/ctgov/{nct_id}` | registry study -> the previous keys, plus `field_notes`, `notes_by_field`, and `procedure_group_labels`. `notes` is still a string array, same texts and order. Bad id -> 400 `invalid_registry_id`; not found -> 404 `study_not_found`; offline and not cached -> 503 `offline_cache_miss`. A cache hit without `refresh` does not touch the network. A live fetch that fails -> 503 `registry_unavailable`; if a copy is already cached, that copy is returned with `stale_fallback: true` and a fact note under `notes_by_field._unscoped`. |
| `GET /api/import/ctgov` | studies in the local cache (the UI's offline demo chips) |
| `GET /api/import/procedure-codes` | `{version, note, codes: [{code, group_label, ships_sample, in_param_library}]}`. `group_label` names the whole code. |
| `POST /api/import/protocol` | multipart `file` (PDF <= 20 MB, else 413) **or** form `nct_id`. For `nct_id`, a committed extraction whose sha256 matches the registry protocol document is returned and the PDF is not downloaded (NCT03930732). Otherwise the PDF is fetched from ClinicalTrials.gov; offline with no cache -> 503 `offline_cache_miss` (the other three NCT ids). Response still has `notice` starting `DRAFT`, `auto_applied: false`, and candidates with `source_page`, `quote` (<= 25 words; a clipped quote also ends with `...`), `confidence`, and per-procedure evidence. Also `procedure_group_labels`, `llm_accuracy: "unmeasured"`, `llm_accuracy_note`. |
| `POST /api/import/protocol/apply` | design + the visits a human accepted -> new design with `visits` replaced and `"visits"` removed from `missing_fields`. Also `cleared_fields` ( `["visits"]` when that flag was present). Never called automatically. |
| `POST /api/import/protocol/review` · `GET …/review/stats` | logs accepted / edited / rejected / added, plus optional `bulk_accepted`. The share excludes bulk-accepted rows. A line with no `bulk_accepted` value stays unknown. |

Every successful import, extraction, apply and review writes an audit entry (A7's chain, through A5's adapter). If the audit
can't be written, the request fails with 503 `audit_unavailable` and no result is returned.

**Identity (URS-023).** In A5's app the role comes from A7's registry through `deps.resolve_identity`, which is in this
tree. A claimed `X-Role` that differs -> 403 `role_mismatch`; an unknown user -> 403 `unknown_user`. Apply and review
are human confirmations: anonymous -> 401 `identity_required`, viewer -> 403 `forbidden_role`, an `ai:*` name that
reaches the router -> 403 `ai_confirmation_forbidden`. Inside A5's app `ai:extractor` does not reach that check:
`deps._USER_RE` rejects the colon and returns 400 `invalid_identity`. Import and extraction stay open to anonymous
callers (public data, audited as `anonymous`). On the 2026-10-16 ET re-run, `test_real_app_takes_the_role_from_the_registry`
passed (role mismatch, unknown user, a registered reviewer with no `X-Role` -> 200, viewer apply -> 403). It still
skips, rather than fails, if `resolve_identity` or the user registry is missing; the router then uses the headers.
Standalone confirmations (anonymous 401, viewer 403, `ai:extractor` 403) are `test_only_a_person_can_confirm`.

**The demo uses NCT03930732 (BOREAS):** a Regeneron/Sanofi biologic, the largest-but-one site network (275 sites, 24 countries),
completed with actual enrolment, and its protocol is posted on ClinicalTrials.gov. The protocol's Schedule of Activities

end, offline. Drug type for both dupilumab trials is `biologic` because of the INN stem `-mab`: the registry itself types the
intervention as DRUG (the note says so).

**Measured numbers (honest scope).**
- *Geocoder* (offline GeoNames, no web geocoder): on every site that has a registry geoPoint (819 sites, 4 trials), the city/state/
  country lookup matched **816 / 819 (99.6 %)**. Of the matches, **810 (99.3 %)** fall within 25 km of the registry point and 809 within
  0.5 km; the worst is 363 km. The near-zero median means the registry's geoPoints coincide with GeoNames city coordinates, so
  this measures city-name matching (city centroids), not facility location. Sites the index can't place stay unresolved
  (lat/lon empty, listed); a country centroid is never guessed. 3 BOREAS sites are placed only to state level, and the note says so.
- *Extraction, deterministic table parser* on the synthetic text PDF (`tools/make_synthetic_protocol.py`, 5 pages, SoA on
  pages 3–4): **7 / 7 visits, 7 / 7 weeks, 1 / 1 windows, 50 / 50 procedure items (precision 50 / 50, recall 50 / 50)**. That's 100 % on
  a document we generated ourselves; it shows the parser works, not how it does on real protocols.
- *Extraction, LLM vision path*: tested **only with a mocked LLM** (the mock returns the ground truth plus planted defects). That
  tests the validator (clipped quotes, out-of-SoA pages -> confidence <= 0.3, unknown labels -> `other:<label>`, home-dosing columns
  excluded), **not the model**. **Live-model accuracy was NOT measured**: no `ANTHROPIC_API_KEY` exists in this environment.
- *BOREAS cached extraction*: the SoA in that PDF is embedded as page images. The coding agent (Claude Opus 5.5) transcribed it
  from rendered pages at build time (`data/fixtures/protocols/NCT03930732_soa_transcription.yaml`). That yaml has **no**
  `human_verified` key. `tools/build_demo_extraction.py` writes `provenance.human_verified: false` into
  `data/fixtures/protocols/extractions/76ead4e1….json`, and `test_boreas_cached_extraction_is_valid` asserts the flag is false.
  The transcription's accuracy was **not** measured. Do not replace that flag with a score.
- *Review log*: `GET /api/import/protocol/review/stats` reads the runtime file
  `data/fixtures/protocols/.cache/review_log.jsonl` (gitignored). This checkout has no such file, so the status is
  `no_reviews` and there is no share. A previous local UI run was 19 accepted, 0 edited, 0 rejected (2026-10-17 01:46 UTC).
  That file, if it is still around, has no `bulk_accepted` key: the share status is `unknown`, and the line is not
  rewritten. It was not a human check. **Real LLM accuracy was not measured** (`llm_accuracy` is `"unmeasured"` on the
  extraction response and on the stats response). Do not print `accepted_unchanged_share` as a model accuracy.

### Review body and stats

```json
{"extraction_id": "76ead4e1…", "design_id": "3b11a429…", "accepted": 19, "edited": 0, "rejected": 0, "added": 0, "unit": "visit", "bulk_accepted": 19}
```

`accepted` still counts every accepted row, including ones accepted together. `bulk_accepted` is how
many of those were accepted without opening the row. It must be `<= accepted`. Omit the key, or send
null, when the client cannot tell. Do not send `0` unless each accepted row was opened.

Every logged row bulk-accepted (this is not 100%):

```json
{"reviews": 1, "accepted": 19, "edited": 0, "rejected": 0, "added": 0, "bulk_accepted": 19, "individually_accepted": 0, "accepted_unchanged_share": null, "accepted_unchanged_share_status": "no_individual_review", "accuracy_unknown_reviews": 0, "llm_accuracy": "unmeasured", "llm_accuracy_note": "Real LLM accuracy was not measured."}
```

A line written earlier, with no `bulk_accepted` key, is left unchanged and the share stays unknown
even if a later line records the field:

```json
{"reviews": 1, "accepted": 19, "edited": 0, "rejected": 0, "added": 0, "bulk_accepted": null, "individually_accepted": null, "accepted_unchanged_share": null, "accepted_unchanged_share_status": "unknown", "accuracy_unknown_reviews": 1, "llm_accuracy": "unmeasured", "llm_accuracy_note": "Real LLM accuracy was not measured."}
```

The share is a number only when every line recorded `bulk_accepted` and at least one row was
accepted, edited, or rejected one by one. Then `accepted_unchanged_share_status` is
`"review_log_only"` and the numerator is `accepted - bulk_accepted`. An empty log is `"no_reviews"`.
Show a percentage only for `"review_log_only"`, and do not call it LLM accuracy.

## Known risks
- `DEMO_OFFLINE=1` with a study that isn't cached -> 503 `offline_cache_miss`; only the 4 NCT ids above are cached.
- With a key and no cache, image-only SoAs go to the LLM (sends up to 8 page images to Anthropic, up to 180 s, one retry).
- Registry data in the fixtures is a snapshot (2026-10-16). The terms ask distributors to keep it current: `refresh=true`
  re-downloads it.
- GeoNames name matching can pick a same-named city in the right country (the 363 km worst case); state is used when the
  registry gives one.
