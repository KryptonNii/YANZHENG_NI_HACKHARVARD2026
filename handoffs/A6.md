## How to run

From `api/`, start the API on A6's port with `uv run --project . uvicorn trialpilot_api.main:app --port 8006`. Tests use temporary databases. The evaluation artifact and reproducible ground truth are in `data/fixtures/ops/`.

## Not done / stubbed

- Feed state and alert/intervention state are in memory and reset when the API process restarts; this supports the offline demo, not durable production operations.
- External EDC, CTMS, IRT, travel, courier, finance, and vendor connections are simulated only.
- Operations parameters are explicit assumptions unless a sourced A10 parameter alias is available. Their ranges and rationale are included in `ops_params.yaml` and alert provenance.

## Contract deviations

- No shared-contract deviation. The current `EventType` has no `site_activated` value, so CTMS site activation is represented as a completed `vendor_milestone` with a non-critical-path flag. See `handoffs/A6_CONTRACT_CHANGES.md` for a proposal to add a dedicated event type.

## Requests to other agents

- **A1:** Consider adding `site_activated` to the shared `EventType` and generated schema so CTMS site-state records have a direct event representation.
- No blocking requests to A3 or A5; A6 calls A3's `forecast` / `update_with_actuals` and is mounted through A5's router registry.

## Known risks

- The evaluation is synthetic and covers three deterministic seeds, not clinical validation. The estimator correctly stays inconclusive for one true no-effect case with seed 7.
- Alert thresholds and un-sourced costs, emissions, and time values are assumptions; impact estimates must be read with their provenance and ranges.
- API process restart discards the current simulation run and its event replay history.

## Demo notes — command-center minute

1. Run the API on port 8006. Use an editor identity (`X-User` and `X-Role: author` in the local API test setup).
2. `POST /api/ops/demo-40/simulate` with `{"seed":42,"speed":0}`; the response labels the feed simulated and starts around day 406.
3. Open `GET /api/ops/demo-40/health`, then `GET /api/ops/demo-40/alerts`; open a drug-overstock or query-backlog alert to show evidence and provenance.
4. Create an intervention from that alert using one of its recommended actions, change it to `in_progress`, then `POST /api/ops/demo-40/clock` with `{"advance_days":42}`.
5. Show `GET /api/ops/demo-40/effects/{intervention_id}` and `/stream`; point out the estimate's confidence range and explanation, then compare scripted intervention verdicts with the withheld ground truth in `data/fixtures/ops/evaluation.json`.
